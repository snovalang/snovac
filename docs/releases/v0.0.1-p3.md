# Snovac 0.0.1-p3

## Compiler layout

Implementation is grouped by compiler phase and runtime category: `frontend/`, `semantic/`, `backend/native/`, `runtime/bytecode/`, `runtime/value/`, `runtime/eval/`, `runtime/concurrency/`, `builtin/`, and `driver/`. The root `Makefile` lists these source groups explicitly. Architecture and ownership decisions are documented in `docs/architecture/compiler-modules-and-memory.md` and `docs/architecture/memory-management-rag.md`.

## Memory management

- The AST evaluator uses private regions for calls, lexical blocks, loops, and match arms. Small regions start with 4 KiB arena blocks.
- Escaping AST values now retain only the regions that own nodes in the reachable value graph, including strings and closure environments. If graph traversal cannot allocate scratch memory, all active and retained regions are conservatively kept alive.
- Non-escaping region data and array buffers are released at scope exit. Escaping regions remain alive until `sn_eval_run` ends; this release does not claim per-object reclamation or general leak freedom for the AST evaluator.
- The bytecode VM continues to use explicit reference counting, moves, and scope drops, with cycle-forming stores rejected.

## Validation

The compiler and runtime library build with the repository's warning flags. `make -q` reports no pending build work, and `git diff --check` passes. The test suite was not run for this checkpoint.
